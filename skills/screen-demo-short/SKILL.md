# Screen-Demo Short

Optimize for one viewer outcome. A short demo is not a sped-up recording of every click.

## Workflow

1. Read the shared [short-form rules](../favstash-shortform/references/shortform-rules.md) and [`references/demo-guide.md`](references/demo-guide.md).
2. Create a dated run with style `screen-demo-short`; record screen captures and product assets in the ledger.
3. State the before/after outcome, then select the smallest action path that proves it.
4. Remove loading, searching, cursor wandering, mistakes, and steps the viewer does not need. Never fabricate a result the product did not produce.
5. Recompose for 9:16 with crops, close-ups, staged panels, or temporary full-screen details. Keep labels and controls readable at phone size.
6. Use cursor/tap animation to lead attention, then get out of the way. One visual focus per beat.
7. Add narration or concise text; avoid narrating every obvious click. Mask private data and notifications.
8. Verify timing against the actual interaction, then finish with `$shortform-review`.

Use `$split-screen-short` instead when a persistent speaker or reaction is essential. Use `$motion-graphics-short` for a fabricated conceptual UI animation rather than a real workflow demonstration.
